# 開發流程需求

## 測試驅動開發

本專案的前端與後端皆必須採用 TDD（Test-Driven Development，測試驅動開發）。每項新功能、行為變更與缺陷修正都應依序執行以下循環：

1. **Red**：先撰寫一個描述預期行為且目前會失敗的測試。
2. **Green**：只加入足以讓測試通過的最小實作。
3. **Refactor**：在所有測試持續通過的前提下改善程式結構。

## 實施原則

- 功能程式碼與對應測試必須一併提交，不得以事後補測試取代 TDD 流程。
- 後端測試放在 `backend/tests/`，並比照 `backend/app/` 的模組結構；前端使用 Vitest，測試放在 `frontend/tests/` 並以 `*.spec.ts` 命名。
- GPIO 與計時操作須以模擬物件或替代實作隔離，使自動化測試不依賴實體 Raspberry Pi。
- 實體硬體測試用於補充自動化測試，不可取代 Red–Green–Refactor 循環。
- Pull Request 必須列出新增或更新的測試，以及實際執行的測試指令與結果。
